# Personal Blog

A single-page personal blog built with React 18 and Vite. Posts live in Supabase (with local fallbacks), routing is hand-rolled on the History API, and the design is a custom editorial system — no React Router, no CSS framework theme, no CMS.

## Quick start

```bash
npm install
npm run dev    # dev server on http://localhost:3000 (opens browser)
npm run build  # production build → dist/
```

There is no test suite or linter.

## Architecture

**Routing.** All routing lives in `src/App.tsx`: `parsePath()` maps `window.location.pathname` to a view, `pushPath()`/`go()` push clean URLs, and a `popstate` listener handles back/forward. Views: home, archives, categories, tags, about, article, tagged, category, admin. Route components are lazy-loaded so each page only fetches its chunk on first visit.

**Data.** Posts are served by a Supabase Edge Function (`src/supabase/functions/server/index.tsx`, a Hono router on Deno; routes are prefixed `/make-server-860c354e/`). Storage is a key-value abstraction over a Postgres table, with posts under `post:{id}` keys. Two hooks fetch data: `useBlogPosts` (list, content stripped server-side) and `useBlogPost(id)` (full content). If the API errors or returns nothing, `src/data/fallbackPosts.ts` is displayed instead.

**Articles.** Markdown renders through react-markdown. Heavy dependencies load only when the content needs them: KaTeX when the post contains `$...$` / `$$...$$` math, the syntax highlighter when it contains fenced code blocks. Posts with neither pay zero cost. Articles with two or more `##` headings get a sticky table-of-contents rail.

**Styling.** Tailwind utilities plus a custom editorial design system in `src/index.css`, driven by CSS custom properties (`--bg-surface`, `--text-tertiary`, `--text-article-*`, …) and toggled by a `dark` class on `<html>`. Article prose: 780px measure, 17px body at 1.72 line-height, 34px titles. Prefer the semantic classes (`editorial`, `meta`, `prose`, `hero`) over raw Tailwind for anything that should match the editorial tone.

**Do not edit** the autogenerated files `src/supabase/functions/server/kv_store.tsx` and `src/utils/supabase/info.tsx`.

## Writing posts

The admin panel is only rendered in dev builds — open it via the `+` button (bottom-right) or the `/admin` route. It supports creating, editing, deleting, and importing posts from `.md` files with YAML frontmatter:

```markdown
---
title: Post title
date: 2026-06-07
author: Yuan Wang
category: Quant
tags: options, vol, quant
readTime: 14 min read
excerpt: One-paragraph summary shown in lists.
---

Body in GitHub-flavored markdown. Math ($...$) and fenced code blocks
are supported; images become captioned figures (alt text = caption).
```

See `posts/` for complete examples.

## Admin writes

Read routes are public. Create, update, delete, and migration requests require a server-side admin key:

```bash
supabase secrets set BLOG_ADMIN_KEY="your-long-random-key"
```

The admin UI asks for that key and stores it only in `sessionStorage` for the current browser session. `VITE_ADMIN_KEY` is intentionally not used for authorization because Vite variables are bundled into client code.

If `BLOG_ADMIN_KEY` or `ADMIN_KEY` is not configured in the Supabase Edge Function environment, write routes return `503` and leave existing content untouched.

## Build & deploy

RSS is available at `https://ynuwng.com/rss.xml`, with automatic feed discovery in the page head. The Vite RSS plugin reads the public article API during every build and emits titles, summaries, dates, authors, categories, and stable article links. The dev server serves the same feed at `/rss.xml`. API errors fail the build so a failed refresh leaves the previously deployed feed intact; sample fallback posts are never published to RSS. A successful empty response produces an empty feed.

GitHub Actions rebuilds and deploys hourly (at minute 17), on pushes to main, or manually via workflow dispatch. Backend article changes appear after the next successful deployment; scheduled runs can be delayed by GitHub. The canonical domain is configured in `scripts/rss.mjs`.

`npm run build` emits to `dist/`, split into `react-vendor`, `markdown-vendor`, and per-route chunks. Assets ≥10KB get `.gz` and `.br` companions, and the `_headers` file (in `public/`, copied to `dist/`) configures Cloudflare to serve the pre-compressed files. `console.log` calls are stripped in production. The `dist/` directory is committed, so a production build should accompany any change meant to ship.
